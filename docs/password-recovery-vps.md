# Відновлення та зміна пароля — h00k.top

## Механізм

У формі входу є **«Забули пароль?»**, а в налаштуваннях профілю — **«Зміна пароля»** з підтвердженням через email. Обидві дії надсилають лист із посиланням. Для локальних акаунтів email/пароль (на VPS) посилання відкриває `https://h00k.top/#reset-password/<одноразовий-токен>`: токен у URL-фрагменті не надсилається в HTTP GET.

На VPS в `/data/accounts.json` зберігається **лише SHA-256 токена**, із терміном дії 30 хвилин. Після використання посилання стає недійсним, а попередні локальні сесії завершуються. Є обмеження частоти запитів.

Для старих Firebase email/password акаунтів лист надсилає Firebase Auth. Користувачі, які входять тільки через Google, змінюють свій пароль у Google.

## Налаштування email для локальних акаунтів

**Увага:** без налаштування поштового провайдера листи для локальних акаунтів не відправлятимуться. Код містить інтеграцію з Resend, але секрети не можна комітити до GitHub.

1. Зареєструйте відправника в Resend (https://resend.com/), підтвердьте DNS-домен, з якого будуть надходити листи, та отримайте API-ключ для надсилання.
2. У приватному `~/hook2/.env` на VPS додайте, замінивши приклади своїми значеннями:

```dotenv
RESEND_API_KEY=re_YOUR_PRIVATE_API_KEY
PASSWORD_RESET_FROM_EMAIL=Hook2 <security@your-verified-domain.example>
```

3. Перезапустіть контейнер із актуальним середовищем через контрольований механізм VPS. Саме оновлення GitHub не додає секретних змінних автоматично. Не надсилайте API-ключі у чат, Issues або публічні логи.
4. Перевірте відправлення листа та перехід за посиланням зі звичайного email/пароль акаунта. Якщо немає доставки, перевірте конфігурацію відправника та журнал сервісу. Без налаштованого Resend форма показуватиме помилку відправлення.

Під час повторного ручного розгортання використовуйте описану в `docs/vps-auto-deploy.md` процедуру. Агент VPS перевіряє успіх GitHub Actions **Validate** перед установленням змін.

## Перевірка функції

- Відкрийте форму входу → «Забули пароль?» → надішліть email зареєстрованого локального акаунта.
- Відкрийте лист, задайте новий пароль, перевірте вхід із ним та відмову старого пароля.
- Перевірте, що повторне відкриття того самого посилання не змінює пароль.
- Увійдіть і натисніть у профілі «Надіслати лист для зміни пароля» — повинен відбутися той самий email-процес.
- Перевірте email/password Firebase-акаунт; його лист формується Firebase Auth.

## Помилка Firebase: “Your request to reset your password has expired…”

Це повідомлення показує стандартний Firebase action handler, а не локальна сторінка VPS. Помилка на щойно отриманому листі також можлива через обмеження або розбіжність API-ключа Firebase.

На сайті реалізована власна українська сторінка перевірки Firebase-коду з `verifyPasswordResetCode` та `confirmPasswordReset`.

**Потрібна одноразова зміна в Firebase Console**, яку GitHub/VPS автоматично зробити не можуть:

1. Відкрийте [Firebase Console → Authentication → Templates](https://console.firebase.google.com/project/knowledgeable-text-whh41/authentication/emails) для проєкту `knowledgeable-text-whh41`.
2. Відкрийте шаблон Password reset (значок олівця) → **Customize action URL**.
3. Введіть точну адресу: `https://h00k.top/__/auth/action` і збережіть.
4. Запросіть **новий** лист відновлення з `h00k.top`. Старе посилання з Firebase Hosting не перенаправиться автоматично.

Firebase застосовує action URL до всіх шаблонів, однак у Caddy лише `/__/auth/action?mode=resetPassword` обробляється нашим сайтом; інші дії Firebase та Google OAuth як і раніше проксіюються на Firebase Hosting.

Якщо **новий** лист одразу показує недійсний код, відкрийте [Google Cloud Console → API Keys](https://console.cloud.google.com/apis/credentials?project=knowledgeable-text-whh41). API-ключ вебзастосунку Firebase має дозволяти реферери `https://h00k.top/*` та `https://knowledgeable-text-whh41.firebaseapp.com/*`, не виключаючи інших існуючих дозволених реферерів. Також API-ключ має дозволяти Firebase Authentication (Identity Toolkit) API. У Firebase Console → Authentication → Settings → Authorized domains має бути `h00k.top`. Застарілий/обмежений ключ у Firebase action links може вимагати підтримки Firebase.

**Не розміщуйте одноразові посилання з `oobCode` та локальні токени відновлення в публічному чаті або GitHub.**
