# Автоматичне розгортання hook2 на OVHcloud

Ціль: Ubuntu 22.04, користувач `ubuntu`, VPS `57.129.171.244`, сайт `https://h00k.top`. Railway більше не використовується.

Після одноразового встановлення VPS сам перевіряє `main` приблизно щохвилини. Новий commit запускається лише після успішного GitHub Actions **Validate** для цього самого commit у `main`. Гілки та pull requests проходять тести, але не змінюють робочий сайт до об’єднання з `main`.

## Встановлення на вже підготовленому VPS

Docker і GitHub CLI вже мають бути встановлені. Виконуйте команди від `ubuntu`, який авторизувався через `gh auth login --hostname github.com --web` і `gh auth setup-git`.

Для наявного клону `~/hook2` після об’єднання змін у `main` скопіюйте лише цей блок:

```bash
bash -e <<'HOOK2_VPS'
cd "$HOME/hook2"
git fetch origin main
git switch --detach FETCH_HEAD
sudo bash deploy/enable-auto-deploy.sh
sudo journalctl -u hook2-vps.service -n 60 --no-pager
HOOK2_VPS
```

Якщо `.env` ще немає, інсталятор попросить **Telegram Bot Token**. Вставте токен і натисніть Enter; введені символи приховані. Токен зберігається в `~/hook2/.env` із правами `600`. Існуючий `.env` зберігається. Перевірте в ньому `DOMAIN=h00k.top` і `TELEGRAM_BOT_TOKEN`. Google-вхід за замовчуванням використовує вже налаштований домен Firebase; `FIREBASE_AUTH_DOMAIN_OVERRIDE` залиште порожнім. Додайте домен сайту в дозволені домени Firebase за [окремою інструкцією](google-auth-vps.md).

Для нового клону після об’єднання змін:

```bash
git clone --branch main --single-branch https://github.com/maks37614/hook2.git "$HOME/hook2"
cd "$HOME/hook2"
sudo bash deploy/install-docker-ubuntu.sh
sudo bash deploy/enable-auto-deploy.sh
```

Початковий каталог не потрібно видаляти або вручну перемикати для кожного оновлення. Він зберігає приватний `.env` та Git-об’єкти. Робочі версії створюються окремо в `~/.local/state/hook2-vps/releases/<commit>`. Systemd запускає агент від `ubuntu` з доступом до Docker. Нові SSH-ключі або GitHub Actions secrets для цього способу не потрібні.

DNS A має вести на `57.129.171.244`; наявний AAAA — на IPv6 цього VPS. В OVH firewall та Ubuntu мають бути відкриті TCP 80/443. Caddy отримує та поновлює HTTPS-сертифікат; порт 3000 прив’язаний до `127.0.0.1`. Вхідні SSH-правила залишаються відповідно до ваших налаштувань.

## Перевірка запуску

```bash
sudo journalctl -u hook2-vps.service -n 100 --no-pager
systemctl list-timers hook2-vps.timer
sudo docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
curl -fsS https://h00k.top/api/health
```

Перший build потребує завантаження образів і залежностей. Повідомлення `Waiting for successful Validate` означає, що агент очікує тести `main`. Успіх позначається `DEPLOYED <commit> https://h00k.top` у журналі, GitHub status `hook2-vps`, а `/api/health` містить `release` із повним SHA commit. Агент підтверджує однакову версію через localhost та публічний HTTPS.

Після запуску ввійдіть на сайт → сповіщення → підключити Telegram → Start у власному чаті → тестове повідомлення. Перевірте два різні акаунти, цінове правило із закритою вкладкою та стеження після перезапуску. Один бот обслуговує всіх; кожен користувач отримує власне одноразове посилання. Токен бота користувачам вводити не потрібно.

## Оновлення, відкат і дані

- Build виконується під час роботи поточної версії. Перед заміною зупиняється єдиний процес моніторингу та робиться узгоджена резервна копія `/data`.
- Нова версія використовує той самий Docker volume `hook2_hook2-data`: правила, Telegram-прив’язки, локальні сесії, історія, черга й стан видалень зберігаються. Після перезавантаження VPS Docker відновлює контейнери, systemd — перевірку оновлень.
- При невдалому запуску або HTTPS-перевірці агент повертає попередній image. Поточні дані не замінюються старою копією. Резервні копії залишаються для ручного відновлення при потребі.
- Зберігаються три останні успішні версії та десять резервних копій. Копії містяться у `~/.local/state/hook2-vps/backups` із закритими правами; переносьте потрібні копії на інший диск/хост.
- Після помилки повторні спроби відкладені на 5, 10, 20, 40, потім 60 хвилин. Новий commit перевіряється одразу після CI.

Для негайної повторної спроби після виправлення DNS/оточення:

```bash
touch "$HOME/.local/state/hook2-vps/retry.request"
sudo systemctl start --no-block hook2-vps.service
```

Щоб тимчасово призупинити оновлення, виконайте `sudo systemctl stop hook2-vps.timer`; поточний сайт продовжить працювати. Відновлення: `sudo systemctl start hook2-vps.timer`. Ручна резервна копія: `sudo bash ~/hook2/deploy/backup-vps.sh`.

Не запускайте паралельну репліку моніторингу і не видаляйте Docker volumes під час оновлень. Дані старого Railway не відновлюються автоматично зі старих snapshot: чинний том є джерелом серверного стану.

## Реєстрація та оплачені строки

Форма реєстрації більше не вимагає коду. Новий акаунт отримує 3 дні повного доступу; потім залишаються Скрінер і Відтворення. Для призначення власника адміністратором та видачі іменних кодів на потрібний строк використовуйте [керування доступом](access-management.md). Дані доступу зберігаються в тому `/data` і включаються до наявних приватних резервних копій.
