# Біржові дані на VPS

Схема розрахована на один процес `hook2` з одним постійним томом `/data`. Публічні дані спільні для акаунтів; правила доступу, стеження та Telegram-одержувачі залишаються персональними.

## Транспорт

- Усі серверні біржові HTTP-запити проходять через `server/exchangeGateway.ts`. Браузерні публічні GET-запити перетворюються на авторизований `/api/market/source`; це не відкритий проксі: дозволені лише визначені публічні маршрути й хости.
- Однакові паралельні GET-запити об'єднуються. Кеш обмежений 2000 записами та 32 МіБ. Короткий кеш поточних даних відділений від історії; невдалі відповіді не стають успішними даними.
- Підписані приватні запити не кешуються, не об'єднуються та не повторюються автоматично. Особисті ключі не використовуються як спосіб збільшення IP-лімітів.
- Браузерні потоки проходять через `/api/market/stream`. Сесія передається першим кадром, не в URL. Сервер перевіряє сесію під час підключення і далі щохвилини; межа — 32 браузерні підключення на акаунт.
- `server/exchangeStreamPool.ts` об'єднує підписки графіків, стеження та щільностей. Binance має спільні з'єднання Spot / Futures Public / Futures Market, Bybit — Spot / Linear. Повідомлення роздаються лише підписникам відповідної теми. Новий підписник Bybit отримує відновлений актуальний snapshot стакана.
- Пропуски послідовності Binance спричиняють повторну синхронізацію. Після втрати свіжої ціни фоновий worker не генерує нові сигнали на старому значенні.

## Обмеження

Внутрішні межі навмисно нижчі за загальні опубліковані ліміти: Binance — 900 одиниць ваги за хвилину; Bybit — 80 HTTP-запитів за 5 секунд. Додатково діють ваги endpoint/limit, окремі п'ятихвилинні бюджети статистики та funding, не більше чотирьох HTTP-запитів одночасно на біржу, короткий строк очікування та обмежена черга. Загальна вага з заголовків Binance також враховується.

У межах тих самих 900 одиниць фонові запити та додаткові аналітичні дані Binance використовують не більше 45% бюджету, а прогрів денної історії для позначок максимумів/мінімумів — не більше 18% (входить у ці 45%). Решта зарезервована для спільних котирувань, каталогів інструментів і свічок графіків. Ці запити також отримують наступне вільне HTTP-з'єднання раніше за необов'язковий прогрів. Позначки історичних діапазонів можуть заповнюватися поступово під навантаженням; це не повинно блокувати список монет або свічки. Приватні операції залишаються без повторного надсилання і під загальним лімітом.

Шлюз обмежує чергу разом із мережею 12 секундами. Спільний feed котирувань і завантажувач свічок очікують до 13 секунд, щоб не відкидати його результат раніше. Клієнт списку монет дозволяє завершитися двом серверним спробам. Підтверджена сервером помилка джерела не запускає повторні запити через той самий relay; відсутня історія повертає HTTP 503 із `sourceUnavailable`, а графік показує повідомлення та кнопку повторення.

Для WebSocket: не більше 100 спроб відкриття за п'ять хвилин на процес, підписки пакетами до 10 тем, максимум чотири команди за секунду, до 400 тем на спільне з'єднання. Heartbeat виконується централізовано. Клієнта з переповненим буфером сервер від'єднує для повторної синхронізації, а не накопичує необмежену чергу.

HTTP 403/418/429/451 і біржові повідомлення про обмеження призупиняють доступ. `Retry-After` враховується; альтернативний домен не створює нового бюджету. Паузи зберігаються в `/data/exchange-cooldowns.json` і переживають перезапуск. Без зазначеного строку для IP ban/451 використовується консервативна пауза. Зміна IP, проксі та обхід регіональних заборон не реалізовані.

Джерела правил: [Binance REST/IP limits](https://developers.binance.com/en/docs/products/spot/rest-api), [Binance Futures market data/weights](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data), [Bybit rate limits](https://bybit-exchange.github.io/docs/v5/rate-limit).

## Перевірка власником

Після входу на сайті авторизований запит `fetch('/api/market/connection-status').then(r => r.json())` показує активні/очікувані HTTP-запити, попадання в кеш, об'єднані запити, строк паузи та число потоків/підписників. Токени й приватні ключі не включаються у відповідь.

Публічний read-only `/api/dom/status` також містить `marketGateway`: сумарну вагу за останню хвилину, вагу фонової історії, кількість активних/очікуваних запитів, `queueTimeouts` (запит не вийшов із внутрішньої черги) та `upstreamTimeouts` (мережевий запит почався, але не завершився вчасно). Це накопичувальні лічильники від запуску процесу; вони не містять сесій, ключів, символів або даних акаунтів. Остання помилка не означає, що джерело досі несправне: актуальну свіжість показує `marketSources`.

Перевіряйте журнал контейнера, RSS/CPU процесу, вік останніх ринкових даних, чергу Telegram та вільне місце тому. При недоступності даних UI має показувати відсутність джерела; повторні сканування не повинні обходити паузу. Не видаляйте файл паузи лише для того, щоб повторювати відхилені біржею запити.

Час VPS має бути синхронізований: `timedatectl show -p NTPSynchronized`. Worker відкидає цінові події, час яких відрізняється від поточного більш ніж на 15 секунд.

Для оновлення використовується наявний автодеплой `main → Validate → VPS`: резервна копія зупиненого тому, новий Docker image, перевірка health/release, відкат образу при збої. Додаткових npm-команд вручну на VPS не потрібно.

Після цього оновлення перезавантажте раніше відкриті вкладки, щоб браузер перейшов на серверний транспорт. Запити старої версії «Розумного аналізу» отримують повідомлення про оновлення замість несумісного формату даних; актуальний клієнт використовує схему 2.

Власник може зупинити конкретне джерело, поки уточнює права на дані: у приватному `~/hook2/.env` встановити `MARKET_DISABLED_EXCHANGES=binance,bybit` (або одну назву) та перестворити контейнер застосунку: `sudo docker compose -p hook2 -f compose.yaml -f compose.vps.yaml up -d --no-build --force-recreate hook2`. Нові HTTP/WS-звернення до вимкненого провайдера не виконуються. Для відновлення потрібне порожнє значення й такий самий перезапуск. Це керування джерелом, а не підтвердження ліцензії.

Не масштабуйте `hook2` кількома незалежними процесами на одному IP: для цього спочатку потрібен спільний міжпроцесний бюджет і спільний collector. Тести з 1000 читачами/підписниками перевіряють об'єднання запитів і потоків на імітованій біржі; вони не є доказом місткості цього VPS для 1000 повноцінних одночасних сесій. Практична місткість залежить від кількості унікальних тем, графіків, worker-правил та трафіку.

## Достовірність

«Розумний аналіз» використовує справжні свічки, обраний стакан, історію OI та поточний funding. EMA 200 відсутня при недостатній історії. Розрахунковий сценарій ATR та оцінка POC позначені як розрахунки. Відомості про гаманці, концентрацію холдерів, особи учасників, приховані заявки та новини без джерела не вигадуються. Відсутність funding не підміняється нулем і не підтверджує залежний сигнал. 5-хвилинна волатильність розраховується за завершеною 5-хвилинною свічкою; неперевірені оцінки з 24-годинного діапазону вилучені.
