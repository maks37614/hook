# h00k Terminal — перевірка спільного потоку Binance aggTrade

## Поточний стан

Спільний потік публічних угод **Binance aggTrade за замовчуванням увімкнений** для вкладок одного походження (origin) і вікон h00k Desktop, якщо браузер підтримує `BroadcastChannel` та `navigator.locks`. Це спільне підключення **між вкладками одного браузерного профілю**, а не між усіма користувачами сайту через VPS. Дані Bybit, персональні сповіщення, моніторинг і сканування не змінюються. Якщо браузер не підтримує потрібні API, використовується попередній прямий WebSocket.

Це навмисний запобіжник: для відображення обсягів покупок/продажів, дельти й поглинання заявок недостатньо отримати тільки найновішу угоду — треба гарантувати безперервний ряд aggregate trade ID.

## Архітектура

- Один Web Lock на публічний ключ `marketType:symbol` обирає вкладку-власника.
- BroadcastChannel розсилає лише публічні агреговані угоди Binance.
- При закритті власника наступна вкладка автоматично перебирає право на WebSocket.
- При відсутності сигналів власника використовується тимчасовий прямий WebSocket.
- Повторні aggregate trade ID не збільшують обсяг вдруге.
- Пропущені ID відновлюються через Binance `aggTrades?fromId`; дані приймаються лише якщо кожен ID у проміжку підтверджений.
- Відновлення обмежено двома сторінками по 1000 угод і максимум двома спробами за 60 секунд на потік; futures REST може мати значну IP-вагу.
- Якщо точність відновити неможливо, система позначає дані неповними, блокує неперевірені обсяги та показує попередження в HookChart, зберігаючи незалежний стакан.
- Для Bybit цей експеримент не вмикається.

## Увімкнення й безпечний відкат

`VITE_H00K_SHARED_BINANCE_TRADES` — **прапорець під час збірки Vite**, не runtime-перемикач. Значення `1` увімкнене за замовчуванням у коді, Dockerfile та `compose.yaml`. Compose передає змінну в Docker `ARG`, далі — у build `ENV`, тому `docker compose up --build` застосовує вибір.

```bash
cd /home/ubuntu/h00k
git pull --ff-only origin main
docker compose up -d --build --no-deps app
docker compose ps
```

Для негайного відкату встановіть `VITE_H00K_SHARED_BINANCE_TRADES=0` у VPS `.env` і **перезберіть** образ:

```bash
cd /home/ubuntu/h00k
# Спочатку задайте VITE_H00K_SHARED_BINANCE_TRADES=0 у файлі .env
docker compose up -d --build --no-deps app
```

Перемикач не впливає на Bybit і не потребує міграцій PostgreSQL. Після оновлення існуючі вкладки варто перезавантажити, щоб отримати новий JavaScript-бандл.

## Перевірки перед production

1. `npm run lint` та `npm test`.
2. Дві вкладки одного браузера з однаковим Binance Futures символом: рівно один власний upstream WS, однакові послідовності trade ID та обсяги.
3. Окремо spot, Unicode-символи, кілька таймфреймів тієї самої монети.
4. Швидкий закрив/відкрив вкладку-власника; перевірка Web Lock takeover.
5. Пропущена подія BroadcastChannel, вимкнення мережі та перезапуск Binance WS: спочатку перевірка gaps, потім оновлення обсягів.
6. Завеликий gap або Binance REST HTTP 429: жодних неперевірених значень дельти й відсутність циклу частих запитів.
7. Тривале тло iOS/desktop, режим сну, відновлення Chrome, кілька вікон h00k Desktop.
8. Порівняння CPU, RAM, WebSocket-count, REST weight, затримок та розрахунків із режимом без relay.

## Обмеження

- У вкладках різних браузерних профілів, на різних пристроях та між різними користувачами дані **не** об'єднуються; це не загальний VPS-ретранслятор.
- Якщо відновлення пропущених trade ID не підтверджене, аналітика обсягів блокується як неповна, щоб не показувати хибні Delta/CVD.
- **Успішні unit-тести й CI не замінюють перевірку на реальних біржових потоках**, особливо на iOS/Android після фонового режиму.
