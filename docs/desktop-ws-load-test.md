# h00k Desktop — контрольований вимір навантаження WebSocket

Цей тест не створює штучних торгових запитів і не звертається безпосередньо до бірж. Він знімає лише агреговані показники вже запущеного VPS через наявний захищений GET /api/ops/market-data. Живі графіки, скринер і сповіщення не змінюються.

## Підготовка один раз

Змінна H00K_OPS_TOKEN в .env повинна мати щонайменше 32 байти. Якщо вона вже налаштована, не змінюйте її. Якщо ні, на VPS виконайте openssl rand -hex 32 та запишіть отримане значення в .env як H00K_OPS_TOKEN=... (не публікуйте його та не передавайте в параметрах команд). Після цього запустіть/оновіть лише app:

    cd /home/ubuntu/h00k
    git pull --ff-only origin main
    docker compose up -d --build --no-deps app
    docker compose ps

compose.yaml уже передає .env до контейнера app. Endpoint повертає 404 без сильного секрету; це нормальна захисна поведінка. Ніколи не відкривайте endpoint назовні та не надсилайте токен у чат.

## Порівняння 1, 2, 4, 6 панелей

Відкрийте однакову монету, біржу та таймфрейм HookChart у h00k Desktop. Перевірте, що в кожній панелі потоки живих свічок працюють, а вкладки не згорнуті. Підтримуйте порівнянну фонову активність і ті самі налаштування Liq/щільностей. При зміні кількості панелей дайте застосунку відновитися.

Запускайте фази послідовно, з окремого SSH-термінала VPS:

    cd /home/ubuntu/h00k
    docker compose exec -T app node --import tsx scripts/desktop-ws-load.ts --phase=1 --seconds=40
    # Відкрийте 2 однакові панелі й повторіть:
    docker compose exec -T app node --import tsx scripts/desktop-ws-load.ts --phase=2 --seconds=40
    # Відкрийте 4 панелі:
    docker compose exec -T app node --import tsx scripts/desktop-ws-load.ts --phase=4 --seconds=40
    # Відкрийте 6 панелей:
    docker compose exec -T app node --import tsx scripts/desktop-ws-load.ts --phase=6 --seconds=40

    docker compose exec -T app node --import tsx scripts/desktop-ws-load.ts --compare=/tmp/h00k-desktop-ws-1.json,/tmp/h00k-desktop-ws-2.json,/tmp/h00k-desktop-ws-4.json,/tmp/h00k-desktop-ws-6.json

За бажанням почніть із фази --phase=0 без відкритих панелей. --seconds допускає 10–600 секунд, --interval — 1000–10000 мс. За замовчуванням використовується 40 секунд та 2000 мс. Звіти всередині контейнера зберігаються як /tmp/h00k-desktop-ws-N.json.

Кожний звіт містить лише кількість з'єднань, агрегований обсяг повідомлень, процесорний час, затримки event loop та обсяг пам'яті. Монети, IP-адреси, токени, ідентифікатори користувачів та історія ліквідацій не копіюються в звіт.

Для копіювання звітів на VPS (без секретів):

    docker compose cp app:/tmp/h00k-desktop-ws-1.json ./h00k-desktop-ws-1.json

## Як читати результат

- CPU % of 1 core: навантаження Node-процесу (100% означає приблизно одне повністю завантажене ядро). Це не загальна CPU всього VPS.
- RSS MiB: RAM процесу Node, не всієї системи й не RAM Windows-програми.
- Kline WS clients / Depth WS clients / Liq WS viewers: скільки клієнтів під'єднано до конкретних серверних потоків.
- Kline exchange WS: скільки активних біржових з'єднань має kline relay.
- Kline bytes/s / Depth bytes/s: кількість переданих байтів JSON payload на секунду (без заголовків TCP/TLS/WebSocket і стиснення).
- Event-loop P95 ms: затримка циклу подій Node.
- Коли кількість панелей збільшується, а кількість серверних WebSocket-клієнтів для того самого інструменту залишається близькою до однієї, спільне підключення працює. Число може відрізнятися через інших користувачів, фон, стани відновлення та резервні з'єднання.

Лічильники sentPackets, sentBytes, upstreamCandles — накопичувальні й перетворюються на швидкості на основі початкового й кінцевого знімків одного процесу. Якщо застосунок перезавантажився під час фази, вона вважається недійсною. Скрипт не називає результати «економією від Desktop», якщо паралельно працюють інші користувачі або різні монети.

## Межі вимірювання

Це безпечний інструмент для відтворюваного тесту, а не автоматичний запуск Windows GUI. Він не відкриває торгові термінали і не створює додаткових підписок. Перед висновком про зниження загального навантаження VPS порівняйте декілька повторів у схожих умовах. Навантаження PostgreSQL, Caddy/Nginx, Docker, Windows CPU/GPU, а також ринкові потоки, які обходять HookChart relay, вимірюються окремо.
