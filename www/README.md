# HOOK Paper Bot — окремий PHP-бот для OVH 100 MB

Це симулятор, який читає **готові результати того самого детектора, що живить сторінку «Формації» h00k.top**, бере поточні ціни та 1m-свічки безпосередньо з Binance / Bybit і веде власний віртуальний рахунок на PHP-хостингу. Реальні ордери не надсилає. Торгові API-ключі не потрібні.

## Що працює

- Захищений кабінет: перше встановлення за окремим ключем, власний пароль, хешування, захист форм CSRF, обмеження спроб входу, завершення сесій та зміна пароля.
- Фільтри зі сторінки «Формації»: біржа, spot/futures, таймфрейм, категорія, напрямок, статус, мінімальний обсяг, пошук і пріоритет сортування.
- Додаткові обмеження: мінімальні confidence/confluence/R:R, Breakout або Retest, екстремум, допустима відстань ціни від запланованого входу.
- Усі штатні validation-перевірки обов’язкові: `passed`, `confirmed`, `closedCandleOnly`, `lookAheadSafe`, `enoughData`, `finiteData`, `breakoutConfirmed`; `volume`, `volatility`, `nearbyLevel`, `structure`. Вимкнути їх через панель не можна.
- Фіксовані стоп і ціль, LONG/SHORT на futures, LONG на spot; незалежні від подальшого зникнення формації зі сканера.
- Розмір позиції за ризиком, ліміт загального ризику, резервування маржі, комісія за обидві сторони та несприятливе прослизання. R:R повторно перевіряється за фактичною симульованою ціною входу.
- Баланс, еквіті, реалізований/нереалізований P&L, прибутки, збитки, win rate, profit factor і спостережувана просадка.
- Історія з цінами, кількістю, комісіями, причиною виходу та часом UTC; CSV-експорт, ручний запит закриття, журнал і діагностика відхилених сигналів.

## Розподіл роботи та навантаження

**VPS:** існуючий фоновий сканер продовжує працювати. Новий endpoint `/api/paper/formations` лише читає його пам’ять, не викликає `runScreenerScan`, AI чи біржові API. Одна відповідь на один запуск бота. Навантаження від цього читання невелике, але не нульове: передача JSON і його серіалізація.

**OVH:** PHP перевіряє сигнали, отримує ринкові ціни/історію, розраховує угоди й записує журнал. Котирування запитуються пакетом один раз на комбінацію біржі/ринку за запуск; для відкритих інструментів — до одного запиту 1m-свічок на позицію. Типово до п’яти позицій. Один запуск має бюджет мережевого часу 24 секунди; HTTP timeout — до 7 секунд. Немає постійного демона або безкінечного циклу.

Endpoint вимкнений, поки у VPS `.env` немає `HOOK_PAPER_FEED_TOKEN` довжиною від 32 символів. Це **окремий ключ лише на читання**: він не надає доступу до профілю, сповіщень чи інших API сайту.

## 1. Підготувати VPS один раз

Потрібна серверна частина з цього коміту: `server/paperFeed.ts`, зміни у `server.ts`, `server/marketService.ts`, `server/cronService.ts`. Звичайне копіювання папки `www` не додає endpoint на h00k.top.

1. Оновіть код VPS через звичайний процес розгортання репозиторію.
2. У **приватному** VPS `.env` створіть довільний випадковий ключ, наприклад з результату `openssl rand -hex 32`:

   ```dotenv
   HOOK_PAPER_FEED_TOKEN=ваш_випадковий_64_символьний_ключ
   HOOK_SCREENER_TIMEFRAME=1h
   ```

3. Перезапустіть застосунок із новим середовищем. Для наявного Docker Compose:

   ```bash
   docker compose -p hook2 -f compose.yaml -f compose.vps.yaml up -d --build
   ```

4. Дочекайтеся штатного фонового сканування (перший запуск приблизно через 10 секунд після старту, далі за поточним графіком). Перевірте відповідь `https://h00k.top/api/paper/formations` із заголовком `Authorization: Bearer ВАШ_КЛЮЧ`. Без ключа очікується 401; без налаштованого ключа або свіжого кешу — 503.

Не комітьте справжні ключі, `config.local.php`, файли приватного сховища або резервні копії.

### Який ринок покрито

Штатний фоновий сканер: `all / futures / 1h / minVolume 100000`, **до 75 найліквідніших пар сумарно**. PHP-фільтри типово налаштовані саме на це покриття. Це не всі біржові монети.

Щоб автономно отримувати **15m**, змініть `HOOK_SCREENER_TIMEFRAME=15m` на VPS, перезапустіть застосунок і виберіть `15m` у боті. Це змінює таймфрейм існуючого завдання; новий сканер не створюється. Підтримуються `1m`, `5m`, `15m`, `1h`, `4h`, `1d`; некоректне значення повертається до `1h`.

Додаткові кеші, створені звичайною сторінкою сайту, також читаються, поки вони свіжі. **Вибір таймфрейму чи spot у PHP-панелі сам по собі не запускає сканування на VPS.** Якщо відповідного кешу немає, бот покаже причину й не зробить входів. Кеш із вищим порогом обсягу не видається за повний ринок із нижчим порогом. Фільтр окремої біржі на загальному кеші охоплює тільки її пари, що потрапили до загальних топ-75.

Якщо браузерна сторінка використовує свій прямий fallback до біржі, ці браузерні результати відсутні у VPS-кеші. Бот використовує серверні результати, і не вдає, що бачить стан конкретного відкритого браузера чи його особисті збережені фільтри.

## 2. Завантажити на OVH

Вимоги: **PHP 8.1+**, стандартні JSON, OpenSSL, session, hash; HTTPS; вихідні HTTPS-запити до h00k.top, api.binance.com / fapi.binance.com, api.bybit.com. cURL бажаний; є fallback через `allow_url_fopen`. MySQL, SQLite, Composer і Node.js для PHP-бота не потрібні.

1. Розпакуйте / завантажте **вміст `www`** у публічну папку хостингу OVH (`www` зазвичай є коренем сайту). Завантажувати весь Node/React-проєкт не потрібно. Для хостингу не потрібна папка `tests`.
2. Скопіюйте `config.example.php` у `config.local.php`.
3. Задайте власний випадковий `setup_key` від 32 символів. Це **інший ключ**, не токен каналу формацій і не пароль кабінету. Значення `REPLACE_...` навмисно не працює.
4. Перевірте `data_dir`: типово це `.hook-paper-private` **поруч із `www`, поза публічним коренем сайту**. PHP має мати право створювати/записувати цю папку. Якщо потрібно, створіть її через FTP. За потреби вкажіть абсолютний приватний шлях; ніколи не ставте `777` і не розміщуйте її всередині публічного `www`. Бот відхиляє сховище під `DOCUMENT_ROOT`.
5. Увімкніть SSL у панелі OVH і відкрийте `https://ваш-домен/`. Введіть ключ інсталяції та створіть пароль від 12 символів. Стандартного загального пароля немає.
6. У «Налаштування стратегії та фільтрів» вставте `HOOK_PAPER_FEED_TOKEN` з VPS. Виберіть відповідний таймфрейм і збережіть налаштування.
7. Налаштуйте cron, переконайтеся, що останній запуск і канал свіжі, потім натисніть **«Увімкнути входи»**. До цього нові угоди вимкнені.

`config.local.php` заборонений для HTTP через `.htaccess`. Стан зберігається в приватній папці у PHP-файлі з негайним `exit` перед JSON, а запис — атомарною заміною під `flock`. Навіть без `.htaccess` файл стану не є відкритим JSON. Не залишайте копії файлів `.bak` у публічній папці.

Якщо пароль втрачено, відновіть **весь приватний файл** із резервної копії або замініть лише `passwordHash` у приватному `state.php` на результат `password_hash()` через довірений локальний PHP. Не видаляйте журнал для скидання пароля й не робіть публічний reset-скрипт.

## 3. Автоматичний запуск без відкритої сторінки

PHP-хостинг виконує код тільки під час HTTP-запиту чи cron-завдання. Відкрита сторінка не потрібна, але потрібен **зовнішній планувальник раз на хвилину** або наявний системний cron з такою частотою.

Зовнішній сервіс має вміти надсилати власний HTTP-заголовок:

```text
URL: https://ваш-домен/cron.php
Method: GET або POST
Frequency: once per minute
Header: Authorization: Bearer ВАШ_ОКРЕМИЙ_CRON_КЛЮЧ
```

Ключ cron створюється автоматично під час інсталяції та видимий лише після входу, у «Планувальник, доступ і діагностика». Його можна змінити. **Ключ у query URL не підтримується**, щоб не записувати його в журнали доступу. Планувальник — довірена сторона, якій ви передаєте лише окремий ключ запуску. Заголовок має доходити до PHP як `HTTP_AUTHORIZATION` або `REDIRECT_HTTP_AUTHORIZATION`.

Для системного cron, якщо він доступний на вашому тарифі:

```cron
* * * * * /usr/bin/php /абсолютний/шлях/www/cron.php
```

CLI доступний лише локальному користувачу хостингу; HTTP завжди потребує ключа. Захист від паралельних запусків і частоти частіше 60 секунд вбудований.

**OVH:** офіційна документація описує найчастіший штатний графік як **раз на годину**. Не припускайте наявність щохвилинного cron на безкоштовному тарифі 100 MB. Для хвилинного моніторингу використовуйте зовнішній HTTP cron; немає потреби переносити обчислення на VPS. Деталі: https://docs.ovhcloud.com/en/guides/web-cloud/web-hosting/cron-tasks .

Відповіді: 200 `ok` / `too_soon`, 409 `already_running`, 503 `degraded` / `cooldown`, 401 без правильного ключа. 503 означає, що бот міг зберегти результати моніторингу угод, але джерело чи частина даних недоступні; дивіться панель. Зупинка нових входів не припиняє супроводження відкритих угод — cron має працювати й на паузі.

## Правила симуляції та відновлення

- Вхід — **лише зараз** за отриманою ринковою ціною, з несприятливим прослизанням. Немає заднім числом виконаних входів за красивою історичною ціною. Якщо ціна відійшла від entry більше дозволеного або фактичний R:R < 2, входу немає.
- Стоп і ціль беруться з формації й більше не рухаються; зміни налаштувань не змінюють комісію/прослизання вже відкритих позицій. ID сигналу містить структурні часові якорі детектора; один сигнал виконується один раз навіть після закриття.
- Виходи перевіряються хронологічно за закритими 1m-свічками після хвилини входу. Ціна відкриття свічки враховує геп через стоп. Якщо обидва рівні торкнулися в одній свічці й open не доводить порядок, результат — стоп із позначкою `ambiguous`.
- За target моделюється несприятливе прослизання; вигідний геп не покращує ціну target. Для виходу за поточною ціною через стоп використовується спостережена ціна, яка може бути гіршою за рівень.
- **Хвилина входу часткова:** її загальні high/low могли бути до фактичного входу, тому вони не використовуються. У цій хвилині враховуються лише ціни, реально спостережені ботом. Це може пропустити коротке торкання між запусками; точного тикового відтворення немає.
- Якщо запуск пропущений, бот доганяє до 1000 хвилин історії на позицію за один запуск. За довшої перерви доганяє кількома запусками; не перескакує пропуски. Нові входи блокуються, поки історія відкритих позицій не відновлена або ціна застаріла. Неповна історія позначається в кабінеті, а не підміняється припущенням про прибуток.
- Відмова каналу формацій не заважає перевіряти вже відкриті позиції через біржу. Регіональні відмови/HTTP 403, 418, 429, 451 призупиняють звернення; немає обходу через дзеркальні хости.
- Усі суми — USDT, лише USDT-пари. Spot-short не моделюється. Funding, ліквідації, ставки запозичення, стакан/черга, точність реальних лотів та реальні вимоги до мінімального ордера не моделюються. Плече — лише симуляція маржі, не повна модель ф’ючерсної біржі.
- Еквіті = баланс + нереалізований P&L. Комісія входу списується одразу; при закритті додається gross P&L і списується комісія виходу. Net P&L історії вже включає обидві комісії. Маржа резервується для розміру наступних угод, а не списується як збиток.
- Просадка обчислюється лише за спостереженнями cron, не за кожним тиком. Час виходу за OHLC приблизний: кінець хвилини; open-геп — початок хвилини. Час відображається в UTC.

## Ліміти 100 MB і резервні копії

Код займає значно менше 1 MB без залежностей. Доступні до 10 одночасних позицій (типово 5), до **1000 угод сумарно з відкритими**, до 5000 виконаних ID, до 150 останніх подій. Історія угод не видаляється автоматично. При досягненні ліміту нові входи блокуються, відкриті позиції продовжують супроводжуватися.

Файл стану обмежений 8 MB; для атомарного запису потрібне місце і на тимчасовий файл. Сам тариф також витрачає місце на інші файли/логи, тому контролюйте вільне місце. Бот не може гарантувати квоту за інші файли вашого хостингу. Для великого журналу використовуйте PHP memory_limit щонайменше 128 MB.

Регулярно копіюйте приватний `state.php` через FTP і експортуйте CSV. CSV — звіт, **не** повна резервна копія для відновлення. Для нової інсталяції після заповнення: вимкніть входи, закрийте всі позиції, збережіть CSV і приватний стан, налаштуйте **інший приватний `data_dir`**, пройдіть встановлення заново. Не перезаписуйте стару історію й не залишайте старі приватні дані у публічному корені. Після збою диска/запису перевірте останню успішну дату: невдалий запис не вважається виконаною угодою.

## Перевірка для розробника

```bash
php www/tests/run.php
python3 www/tests/http_checks.py
node --import ./tests/fixtures/offline-network.mjs --import tsx --test tests/paper-feed.test.ts
```

PHP_BINARY можна вказати для Python HTTP-тестів. Вони запускають тимчасовий PHP web server і перевіряють реальні setup/login/logout/password/cron/CSV/CSRF/HTTPS маршрути без зовнішніх запитів. Unit-тести перевіряють облік, LONG/SHORT, гепи, неоднозначні свічки, відновлення пропущеної історії, фільтри, маржу, ризик і атомарне сховище. Є окреме завдання PHP у GitHub Actions.

Це підготовлений до встановлення код; працездатність вихідних запитів і прав FTP саме на вашому OVH перевіряється після завантаження. Справжні паролі, ключі й розгортання хостингу не включені до репозиторію.
